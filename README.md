## Overview

STELLAR is a probabilistic time-series forecasting architecture that combines **five complementary inductive biases** inside a single unified framework:

| Component | Innovation |
|---|---|
| **Koopman Latent Dynamics (KLD)** | Lifts observations into a latent space where dynamics are *linear*; eigenvalues constrained inside the unit disk guarantee stability |
| **Adaptive Spectral Filtering (ASF)** | A hypernetwork produces per-sample complex bandpass filters in frequency space, adapting to each time series' seasonality |
| **Multi-Resolution Temporal Patching (MRTP)** | Patches at scales {4, 8, 16} are encoded independently and fused via cross-scale multi-head attention |
| **Neural-Process Probabilistic Head (NPPH)** | A latent-variable NP head yields well-calibrated predictive distributions via a VAE-style ELBO |
| **Gated Prediction Mixture** | A learned softmax gate routes each sample to the most appropriate predictor at inference time |

### Results Summary

STELLAR achieves competitive performance across 6 standard benchmarks (ETTh1/2, ETTm1/2, Weather, ECL) compared to 8 baselines including NLinear, DLinear, PatchTST, Informer, Transformer, DeepAR, FEDformer, and TimesNet.

| Dataset | MAE | RMSE | sMAPE | CRPS | NLL |
|---------|-----|------|-------|------|-----|
| ECL     | 0.2518 | 0.4987 | 31.37% | 0.2244 | -0.3518 |
| ETTh1   | 0.5126 | 0.7608 | 71.30% | 0.3642 | 0.0044 |
| ETTh2   | 0.3268 | 0.4551 | 35.01% | 0.2401 | -0.3465 |
| ETTm1   | 0.4161 | 0.6640 | 62.83% | 0.3178 | 1.3337 |
| ETTm2   | 0.2615 | 0.3648 | 29.96% | 0.1933 | 22.69 |
| Weather | 0.0523 | 0.0762 | 12.36% | 0.0389 | -2.2639 |

> All results: seq_len=96, pred_len=24, single univariate target column per dataset.

## Quick Start

### 1. Installation

```bash
git clone https://github.com/YOUR_USERNAME/stellar-forecasting.git
cd stellar-forecasting
pip install -e .
```

### 2. Data

The experiments use the standard ETT/Weather/ECL datasets. Download from the [original ETDataset repo](https://github.com/zhouhaoyi/ETDataset) or from Kaggle:

```
kaggle datasets download rahuldray12324/six-datasets
```

Update `DATA_PATHS` in `data/dataset.py` (or set `--data_root` CLI flag) to point to your local copies.

Expected layout:
```
all_six_datasets/
├── ETTh1/Y_df.csv
├── ETTh2/Y_df.csv
├── ETTm1/Y_df.csv
├── ETTm2/Y_df.csv
├── Weather/Y_df.csv
└── ECL/Y_df.csv
```

Each CSV must contain at least one numeric column (the `y` column or any other numeric column is auto-detected).

### 3. Reproduce STELLAR Results

```bash
python experiments/train_stellar.py \
    --data_root /path/to/all_six_datasets \
    --seq_len 96 \
    --pred_len 24 \
    --epochs 20 \
    --gpus 2
```

Results are written to `results/stellar_results.csv`.

### 4. Reproduce Baseline Results

```bash
python experiments/train_baselines.py \
    --data_root /path/to/all_six_datasets \
    --gpus 2
```

### 5. Ablation Study

```bash
python experiments/ablation.py \
    --data_root /path/to/all_six_datasets \
    --gpus 2
```

### 6. Hyperparameter Sweep

```bash
python experiments/hyperparam_sweep.py \
    --data_root /path/to/all_six_datasets \
    --datasets Weather ECL \
    --n_modes 16 32 64 128
```

### 7. Run Everything

```bash
bash scripts/run_all.sh /path/to/all_six_datasets
```

## Using STELLAR Programmatically

```python
import torch
from stellar import STELLAR

model = STELLAR(seq_len=96, pred_len=24)

x = torch.randn(32, 96)          # (batch, seq_len)
mean, var, kl = model(x)         # probabilistic output
# mean: (32, 24)  — point forecast
# var:  (32, 24)  — predictive variance
# kl:   scalar    — KL term for ELBO loss
```

Training with the ELBO loss:

```python
from stellar.losses import gaussian_nll

loss = gaussian_nll(mean, var, y_true) + 1e-3 * kl
loss.backward()
```

## Known Issues & Numerical Stability

- **ETTm1/ETTm2**: These datasets can trigger numerical instability (`inf`/`nan` loss) in early epochs due to large-magnitude raw values. The model uses gradient clipping (`max_norm=1.0`) and AMP mixed precision; restoring the best checkpoint before evaluation recovers stable results.
- **Weather NaN training**: `nan` training loss in later epochs (after a good checkpoint is saved) is safe — the early-stop + best-checkpoint restore mechanism handles this.
- **NoNPHead ablation**: requires `d_lat` to be stored as an attribute on `NPHead`. This is fixed in the current codebase (see `stellar/components.py`).
